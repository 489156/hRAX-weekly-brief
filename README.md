# hRAX-weekly-brief · 랙스

노동법·HR·AI의 공개 원문을 수집하고, 확인 사실·실무 제안·확인 한계를 구분하는 뉴스레터입니다.
저장소 이름은 `hRAX-weekly-brief`(한글 표기: 랙스)입니다. 현재 사이트 제호 「사이」와 공개 주소 `https://sai-newsletter.baze.cloud`는 유지합니다.
디자인의 검은 2px 이음매·파스텔 벤토·읽기 진행 띠는 `DESIGN.md`를 따릅니다.

## 화면과 데이터

| 화면 | 기능 |
|---|---|
| 홈·전체 글 | 실제 게시된 글과 주제 필터, 추가 목록 읽기 |
| 글 읽기 | 원문 링크·발행일·확인일·요약·실무 제안·한계, 목차와 중간 구독 |
| 출처 모음 | 조사한 전체 출처와 정기 수집·수동 확인·보류 구분, 검색과 조사표 |
| 구독·구독 관리 | 이메일·관심 주제·동의 저장, 최초 발급 링크로 본인 신청 삭제 |
| 운영 관리 | 관리자 비밀번호로 수집·게시·이력 확인, 구독자 검색·CSV·개별 삭제 |

기존 견본 4편과 제7호는 새 화면에서 제공하지 않습니다. 기존 구독자 정보와 관리 링크는 보존합니다.
구독은 신청 정보 저장만 제공합니다. 자동 이메일 발송과 이메일 소유 확인은 범위 밖입니다.
미리보기와 공개 데이터는 별개이며, 미리보기의 시험 글이나 구독 내역은 GitHub·배포에 자동으로 포함되지 않습니다.

## 주간 예약과 안전 장치

- `.github/workflows/newsletter.yml`: 화요일 01:00 UTC, 즉 한국시간 화요일 10:00에 시작하는 일정입니다. GitHub 실행 지연이 있을 수 있으며 정각 완료를 보장하지 않습니다.
- 회당 기본 5개·최소 2개·최대 10개입니다. 2개 미만이면 보류하고, 같은 회차·원문 주소·정규화 제목의 중복 게시를 막습니다.
- 원문의 허용 범위·날짜·본문을 확인하고 AI가 짧은 한국어 요약을 만듭니다. 근거 문장 대조와 두 번째 AI 의미 검토를 통과해야 게시합니다. 자동 검토이므로 오류 가능성은 남습니다.
- 유료벽·로그인·수집 제한은 우회하지 않습니다. 홍보성 자료와 확인하지 못한 첨부 내용은 게시하지 않습니다. GitHub Trending은 수동 확인 대상입니다.
- GitHub Actions는 단기 OIDC 증명만 사용합니다. 공개 앱은 허용한 저장소 이름·고유번호·소유자 번호·main 분기·작업 경로·비공개 여부·발급처·대상·만료·서명을 검증합니다.
- `PUBLICATION_ENABLED` 저장소 변수는 **초기값 false**입니다. 공개 반영 승인과 실제 연결 검사 성공 전까지 true로 바꾸지 않습니다.
- 수동 실행의 `verify_only=true`는 자동 게시가 꺼져 있어도 허용하며, 발행 이력 조회만 하고 수집·AI 호출·새 글 생성을 하지 않습니다.

### 최초 연결 순서

1. 비공개 저장소와 `wrangler.jsonc`의 허용 저장소 고유번호를 대조합니다.
2. BAZE 앱 전용 AI 키와 관리자 비밀번호를 확인합니다. 비밀값은 소스나 GitHub에 넣지 않습니다.
3. 미리보기·프로덕션 빌드·모바일·구독·중복·권한 보호를 검사합니다.
4. 별도 게시 승인을 받아 기존 공개 주소에 변경분을 반영합니다. 이 단계까지 예약 자동 게시는 계속 꺼져 있습니다.
5. GitHub 수동 실행에서 `verify_only=true`로 실제 공개 앱 접근을 확인합니다. 미리보기 검사만으로 외부 연결 완료라고 판단하지 않습니다.
6. 연결 성공 후 `PUBLICATION_ENABLED=true`로 활성화하고, 최초 발행과 반복 실행의 중복 방지를 실제 공개 이력에서 확인합니다.

중단된 작업은 같은 회차로 다시 실행합니다. 완료된 수집·요약은 유지하며 이미 게시한 회차는 글이나 AI 호출을 추가하지 않습니다.
원문 확인 실패·검증 제외·발행 보류의 이유는 운영 관리의 회차별 이력에서 확인합니다.

## 개발과 검증

`npm run dev`로 화면과 API를 함께 실행하고, `npm run check`로 로컬 API와 1440·375·402 너비의 사용자 흐름을 확인합니다.
구독 검사는 로컬에서 임시 신청을 만들고 본인 취소 링크로 정리합니다. 공개 주소에서는 검증용 구독을 만들지 않습니다.
`npm run build` 후 `npm run check:production`으로 기존 로컬 Worker가 제공하는 실제 배포용 화면·글별 공유 태그·조건부 새로고침·모바일·파일·CSV 다운로드를 검사합니다.
배포용 검사는 읽기만 하며 새 글·구독 신청을 만들지 않습니다. 기존 공개 데이터의 삭제·덮어쓰기는 별도 동의 없이 실행하지 않습니다.

| 위치 | 역할 |
|---|---|
| `src/content.ts`, `src/topics.ts` | 사이트 문구와 관심 주제 |
| `src/routes.tsx` | 유일한 화면 경로 목록 |
| `shared/sources.ts` | 출처 조사와 자동·수동·보류 분류 |
| `worker/collect.ts`, `worker/editorial.ts` | 안전한 수집·선별·검증·게시 |
| `worker/automation-auth.ts` | 예약 작업의 단기 증명 검증 |
| `scripts/run-editorial.mjs` | 외부 예약 및 미리보기 실행 절차 |
| `schema.sql`, `baze.json` | 구독·발행 저장 구조와 소유자가 볼 표, 필요한 비밀의 이름 |
| `test/` | 수집·AI 스트림·예약 권한과 사용자 흐름 검사 |

필요한 비밀은 `ADMIN_TOKEN`, `BAZE_API_KEY`입니다. `BAZE_API_BASE`는 실행 환경에서 주입받고 서버에서만 읽습니다.
